## Product

- Morcheh ("ant"): SSH-based server management + monitoring for small/medium orgs — add servers over SSH, discover services/files, configure servers, run Ansible playbooks, password vault, uptime checks.
- Frontend is `../frontend` (Next.js, client-side only, calls this API via `NEXT_PUBLIC_API_URL`; CORS origin `http://localhost:3200`).
- Built: servers + folders (SSH only). `internal/api/servers.go`: list (`q` matches name/host/hostname/description/tags, filters folder|`unfiled`/favorites/os/status/tag/auth (`direct=true` = that folder only, not its subfolders), sort, offset paging), `/servers/facets` (counts for filters), CRUD, favorite, duplicate, `/servers/{id}/check`, `/servers/test-connection` (unsaved form), `/servers/bulk/{check,move,tags,delete}`. `internal/api/folders.go`: nested folders (CRUD; delete moves servers/subfolders up).
- `internal/sshprobe` connects with password or private key (+passphrase), reports status (`online`/`unreachable`/`auth_failed`/`host_key_mismatch`/`error`), latency and detected OS (os-release / sw_vers / `ver`). Background re-check: `api/server_monitor.go` checks every server whose `last_checked_at` is older than `SERVER_CHECK_INTERVAL` (default 15s, 0 = off; off in tests), looking every 5 s, 8 at a time, a server still being checked is skipped. Host keys are TOFU: first successful check stores the key; a different key → `host_key_mismatch` until `?trust_new_host_key=true`; changing host/port forgets it.
- Terminal + files over SSH: `internal/sshpool` keeps one shared SSH connection per server (keepalive, idle close after 5 min, lazy SFTP client, uid/gid name cache, replaced when credentials/host key change — `connVersion` in `api/ssh.go`). Get it via `h.conn(ctx, id)` / `h.withSFTP(...)` (retries once on a dead pooled conn). `internal/terminal`: shells live on the backend (PTY `xterm-256color`, 512 KB scrollback replayed on attach, max 10 per server, killed after `TERMINAL_DETACHED_TIMEOUT` (15m) detached). WebSocket `GET /servers/{id}/terminals/connect` (raw chi route, not in the spec; origin checked against `CORS_ORIGINS`): `?session=` reattaches, else new shell with `cols`/`rows`/`cwd`; binary frames = terminal bytes both ways; text JSON: client `resize`, server `session`/`title`/`exit`/`error`; failures close with code 4000+HTTP status. REST: list/rename/close terminals. `api/files.go` (tag Files, `/servers/{id}/files/...`): list, stat, size (du), download (one file with Range, else streamed zip; `inline` only for safe types + CSP sandbox), content read/write (≤5 MB text, mtime conflict 409), upload (raw body PUT, temp file + rename, 409 unless `overwrite`), mkdir, rename, move, copy, delete, chmod, chown, compress (tar.gz/zip) + extract + fetch from URL (background jobs, see Jobs), search (find); `api/disk_usage.go`: `GET /files/usage` (`du -xak -d 1` + `df` + /proc/mounts through `rootShell`, 5 min timeout → 504, ≤500 entries biggest first, other filesystems' mount points flagged in `mount`, `du:` errors counted as `unreadable`). Mutations needing commands run them over exec (`run()`), so the remote needs a POSIX shell + coreutils (zip/unzip optional).
- Live stats: `GET /servers/{id}/stats` (`api/stats.go`) runs `internal/sysstats.Script` over exec (`h.withConn`, retries once on a dead conn) and parses /proc (uptime, loadavg, stat, net/dev sampled 1 s apart, meminfo) + `df -PkT`; ~1.2 s per call. Linux only (422 otherwise). Disks drop pseudo filesystems (overlay kept only at `/`) and dedupe mounts with identical size numbers (bind mounts). Realtime: `GET /servers/{id}/stats/stream` (Huma `sse`, events `stats` / `problem` = `StatsProblem{status, detail, retrying}`, ping comment every 20 s). `statsHub` runs ONE `sysstats.StreamScript` per watched server (loop: a frame per second ending `@end`, df every 10th frame under `timeout 5`), holds the conn with `Acquire`/`Release`, fans out to all subscribers (newest event only, the last one replayed on join), stops 10 s after the last subscriber leaves, restarts the script if no frame for 20 s, retries failures with 2→30 s backoff (404/422 final).
- Open ports: `GET /servers/{id}/ports` (`api/ports.go`, tag Network) runs `internal/ports.Script` (POSIX sh, busybox-safe) over exec: `ss -tulpn` else `netstat`, via `sudo -n` when passwordless (else only the login user's processes are named, `privileged:false`), /proc comm/cmdline/cgroup, systemd unit, and `docker`/`podman inspect`. `ports.Parse` maps published bindings to containers whatever holds the host socket (docker-proxy, rootlesskit, conmon), host-network containers via cgroup id, merges IPv4/IPv6 per owner, labels the service (container image → process/interpreter table in `known.go` → well-known port guess) and flags `sensitive` (DBs/caches). Fixture tests in `internal/ports/testdata`.
- Network map: `GET /network/map` (`api/network.go`, tag Network): scans every server over SSH (`internal/netmap`: `CollectScript` reads interfaces/routes, `ProbeScript` does a TCP connect to the SSH port + ping on shared LAN/VPN addresses and the address Morcheh uses; `netmap` only parses and builds subnets/links, it runs nothing). Keeps the last scan in memory, one scan at a time (it outlives the request; concurrent requests wait); `?refresh=true` rescans. A server that can't be read keeps its `error`, the others still probe it.
- Cron: `api/cron.go` (tag Cron, `/servers/{id}/cron…`): one collect script reads every user crontab, /etc/crontab, /etc/cron.d, periodic run-parts dirs and systemd timers (+ daemon detection, server tz); `history` greps journal/syslog/cron log for last runs (empty with a `note` when none). Edits (add/update/delete/enable jobs, save a whole table as text) carry the table `revision` (hash) → 409 when stale; a bad raw line → 422 at `body.content` with `value` = line number. `run` executes a command once as the job's user (timeout, output capped keeping the start, `truncated`); `timers/action` = start/enable/disable a systemd timer. Root access via `api/privilege.go`: `rootShell` detects root / `sudo -n` / sudo with the stored login password (`runInput` feeds stdin), cached 10 min (`privilegeTTL`) since failed sudo gets logged.
- Storages (tag Storage): `internal/storage` = one `Storage` interface over S3 (minio-go; empty bucket = every bucket as a top-level folder), FTP/FTPS (jlaffaye/ftp), SFTP (pkg/sftp, TOFU host key like servers) and WebDAV (gowebdav); paths are clean absolute, relative to the storage's `root_path`. Each reports capabilities (S3: buckets, share_links, server_copy, ranges · SFTP: ranges · WebDAV: server_copy · FTP: none); unsupported → `ErrUnsupported`. `api/storages.go`: CRUD (secrets sealed, blank = keep), test-connection, check (`?trust_new_host_key`), favorite, `read_only` refuses writes. Background re-check: `api/storage_monitor.go` (same shape as the server monitor, `STORAGE_CHECK_INTERVAL` default 30s, 0 = off) opens a fresh connection and records it, leaving the pooled one alone. `api/storage_files.go` (`/storages/{id}/files/…`) mirrors the server file endpoints (list, stat, size, search, download/zip + Range, content with `expected_modified` 409, upload, mkdir, rename, move, copy, delete, share = presigned URL) plus `POST /storages/transfer` (a background job, see Jobs): streams files between any two endpoints (`server_id` / `storage_id`), creates missing folders, 409 unless `overwrite`, `move` deletes the originals after.
- S3 bucket settings (tag Storage buckets, `api/storage_buckets.go` over `internal/storage/s3_bucket.go`): `/storages/{id}/buckets` create, `/buckets/{bucket}` read (versioning, access derived from the policy, lifecycle, CORS, tags, encryption, object lock; a setting it can't read comes back as a note, not an error) + PUT per setting + `/empty` (every version). Engineer for create/empty/versioning/tags/lifecycle/CORS, Owner for policy/encryption/retention, all refused on `read_only`. Provider refusals (`NotImplemented` etc.) map to 422 "This provider doesn't support that setting".
- Storage insights (`api/storage_insights.go`, `queries/storage_insights.sql`, tables `storage_checks` (every check the monitor/check makes, pruned after `STORAGE_HISTORY`, default 744h) and `storage_usage` (one row per measurement: used bytes, files, folders, top 12 folders jsonb + `other`, SFTP disk total/free via `storage.SpaceOf` (statvfs), `partial` when the 30 min walk timed out; kept 400 days)). `GET /storages/insights?range=24h|7d|30d&tz=` (buckets 30m/4h/1d aligned to local midnight in `tz`; summary, latency series, status changes, activity from transfer/copy/move jobs + schedule runs + database backups, usage history incl. the baseline before the range). Measuring = `POST /storages/{id}/usage/measure` → 202 + job kind `storage-scan` (Operator; one at a time per storage, else 409), plus `startStorageScanner` measuring online storages not measured within `STORAGE_SCAN_INTERVAL` (24h, 0 = off), one at a time; a failure waits a full interval.
- Server insights (`api/server_insights.go`, `queries/server_insights.sql`, migration `create_server_insights`): every check (monitor or manual) goes into `server_check_buckets` (5-minute rollups: checks, failures, latency) + `server_status_changes`; `startServerSampler` reads CPU/memory/root+other disks/network/load over SSH from online Linux servers every `SERVER_SAMPLE_INTERVAL` (5m, 0 = off; non-Linux asked again later) into `server_samples`; all pruned after `SERVER_HISTORY` (744h). `GET /servers/insights?range&tz` (same buckets as storage; `sample_seconds` = 0 when sampling is off). `GET /databases/insights?range&tz` (`api/database_insights.go`): summary per database (incl. `flavor`), bucketed series from the monitor's samples, problem/recovery events. Both policy `active`. New migrations don't run on start: `make migrate-up`.
- `internal/secrets`: AES-256-GCM sealing of passwords/keys/passphrases at rest. Server/storage responses never carry secrets (only `has_password`/`has_private_key`); the exceptions (user decision) are `POST /servers/{id}/credentials` and `POST /storages/{id}/credentials` (`api/credentials.go`, `Cache-Control: no-store`): decrypted secrets of the chosen auth method + public key derived from the private key + host key. Owner level only.
- Jobs (tag Jobs): anything long runs in the background through `internal/jobs` (table `jobs`, in-house runner rather than River/Asynq: one process, so workers polling Postgres would only add latency). `h.jobs.Handle(kind, fn)` (storage: `h.servers.jobs.Handle`) + `submit(ctx, h.jobs, jobs.Spec{...})`; `fn` gets a `*jobs.Task` (`Progress`, `Log`, `ctx` canceled by Cancel). At most `Limit` (4) run at once and `PerRef` (2) per server/storage. Queued jobs survive a restart, running ones become `interrupted`; retry = a new row from the stored params; progress writes are throttled, the log keeps a 32 KB tail, finished jobs go after 30 days. `api/jobs.go`: list, get, cancel, retry, delete, clear finished, SSE `GET /jobs/stream` (`job` / `removed`, empty id = reload; not all of a job's history, so clients reload on connect). `api/file_jobs.go`: `compress`, `extract`, `fetch` (the server runs curl/wget on a URL) and `POST /storages/transfer` answer 202 + `Job`; checks that can fail at once (409 clash, 422 path) still answer before queuing. `move-files`/`copy-files` and `storage-move`/`storage-copy` also answer 202 + `Job` (kinds `move`, `copy`, `storage-move`, `storage-copy`): planned at submit (409/422 at once) and re-planned at run time; a copy removes only its current partial target on failure, a move never deletes anything. `install-fail2ban`/`uninstall-fail2ban` = kinds `fail2ban-install`/`fail2ban-uninstall`, output streamed with `rootShell.execTo` + `lineWriter` (`api/privilege.go`). `Spec.Quick` skips both limits (usually instant work like renames; not persisted, so a retry or restart queues normally). `Progress.Locked` refuses Cancel (`jobs.ErrLocked` → 409) while a step mustn't be interrupted, e.g. a package manager. Once a job has done work, return `errLostPartWay` from inside `withSFTP`/`withFS` so a dead connection doesn't retry and re-plan. A new long operation = register a kind, never block the request. A job holds its SSH conn with `hold` (`api/ssh.go`), or the pool's idle reaper closes it mid-copy.
- Services page (tag apps; the frontend calls them "Services", the code "apps"; migration `create_apps`, `queries/apps.sql`): web services a team uses (address, note, color, critical, accounts) in per-workspace categories. Tables `apps`, `app_categories`, `app_logos` (source `favicon`|`upload`, both kept), `app_accounts` (password sealed), `app_secret_views` (reveal log; snapshots the account label and user name, so rows outlive the account/user, deleted with the service). Access: `kindApp` / `onApp(level)` (grant on one service, or via its workspace); list = `active` + scope. `api/apps.go` CRUD (accounts only from Operator up, never passwords), `app_categories.go` (categories + `PUT /workspaces/{id}/apps/layout`, Engineer on the workspace), `app_secrets.go` (reveal = **Operator**, deliberately lower than a server's Owner-only credentials: the point is the team signs in without asking; every reveal is logged in the same transaction; activity = Owner), `app_logos.go` (`GET` logo with nosniff + CSP sandbox; `PUT` raw image ≤1 MB, type sniffed from the bytes; `refetch-icon`). `internal/appicon` fetches favicons (5 s timeout, ≤3 redirects, http(s) only, no cookies, TLS unverified on purpose for self-signed internal panels, image allowlist by sniffing; private addresses allowed on purpose, but `refuseDial` refuses link-local (cloud metadata), metadata IPs, unspecified and multicast addresses at dial time (redirects and DNS rebinding included) and the client has no proxy, which would dial past that check); create/address change starts it in the background and it writes only `source=favicon` while the address still matches.
- Ansible (tag Ansible, `api/ansible.go` + `internal/ansible`): `ansible-playbook` runs **on the Morcheh host** (`ANSIBLE_PLAYBOOK`, `ANSIBLE_SANDBOX` auto|bwrap|off, `ANSIBLE_RUN_TIMEOUT` 2h), in a bubblewrap sandbox when it works (sees only /usr, /etc, ansible's install and the run's temp folder; **network shared**, so local services stay reachable). Without a sandbox only system admins may run (checked at submit and again in the job). Per run: temp folder (`morcheh-ansible-*`, removed after; `CleanStale` at start) with inventory (stored inventory names, groups = `GroupName(tag)` + `os_<id>`), known_hosts of the trusted keys only (no host key → refused, "Check it first"), decrypted keys, `callback/morcheh.py` writing JSON events to fd 3. `Filter` masks every server secret in output and events. Tables `ansible_playbooks` (unique name per workspace, `revision` = updated_at → 409) and `ansible_runs` (snapshot of content, hosts, options; output capped head 1 MiB + tail 3 MiB; plays/recap jsonb). Run = job kind `ansible-run` (`JobPlace.RunID`; retry-job refuses it: run again from the page); live output in an in-memory hub (`ansibleLive`), saved to the DB every 3 s; `syncRun` ends runs whose job ended without them. SSE `GET /ansible/runs/{id}/stream`: `snapshot` (whole run, first and last), `output{offset,text}`, `event` (apply like `Log.Apply`). Access: playbooks Viewer read / Engineer write on the workspace, runs Operator read / Engineer cancel+delete, **starting a run = Owner on every target server** (a playbook can read the login). Extra vars and playbook text aren't secret storage: Operators read them. A user with only direct server grants has no workspace level, so no Ansible. Module catalog: `GET /ansible/modules` + `/ansible/modules/{name}` (`ansible/modules.go`, `Catalog` caches `ansible-doc --json` by version; categories from name/collection maps, `featured` = the curated main options per module, `free_form` modules); any active user. Needs python3 on targets; modules = what's in ansible's install (ansible-core = builtin only), since the sandbox doesn't see `~/.ansible/collections`. Ansible reports a changed host key on a password login as "Using a SSH password instead of a key is not possible because Host Key checking is enabled".
- Cron jobs = scheduled tasks (tag Cron jobs, `api/schedules.go` + `api/schedule_actions.go` + `internal/storage/sync.go`; tables `schedules`, `schedule_runs`, migration `schedule_actions`). `action` (fixed once made) = `sync` | `archive` (server folder → tar.gz `<base>-2006-01-02_15-04-05.tar.gz` sent to servers/storages, keep newest N) | `fetch` (URL into server folders, `fetchParams.MakeDir` creates the folder) | `script` (saved script re-read each run, or ad-hoc; ≤200 servers, 5 at a time; run links its `script-run`) | `ansible` (playbook + selection re-resolved each run; Owner on every target; links the `ansible-run`) | `service` (start/stop/restart/reload, ≤200; Operator, `force` = Engineer, protected units need force) | `reboot` (≤50, one at a time, waits 15 min for each to come back; `only_if_required`, `skip_if_logged_in` → result notes) | `verify-backup` (database's latest backups, Operator). Per-action fields live in `task` (jsonb), its servers/storages/databases in refs for access re-checks; runs carry `link {kind,id}` and per-target `results[]` with `note`. New actions run as job kind `schedule-run`; only `sync` has a Test run. Sync: one source end (`server_id`|`storage_id` + path) → up to 20 destinations, modes `update` (new/changed: same size and not older = up to date, 2 s slack, 1 min on FTP; never deletes) / `mirror` (also deletes extras; an empty source fails with `ErrEmptySource`, deletes nothing) / `snapshot` (new folder `2006-01-02_15-04-05` per run, prunes beyond `keep` (0 = all), only folders named like that). Excludes: no slash = a name at any depth, with a slash = path from the source; a matched folder skips its contents. `startScheduler` ticks every `SCHEDULE_TICK` (15s, 0 = off), cron parsed in the job's `timezone` (+ `@every`); a run missed while down happens once on start, resuming a paused job doesn't make up runs. Each run = job kind `schedule-sync` (no retry-job; Run now again) **with the access of whoever saved it last (`updated_by` = run_as)**, re-checked at run time: inactive/removed user or a deleted end → `problem` text, nothing runs. Due while the previous one runs → a `skipped` run row; Run now while running → 409. Dry runs report would-be counts (`deleted` = would-be prunes). ≤20 problems kept per destination. Access: Viewer read, Operator run/test/cancel, Engineer write; saving also needs Operator on the source and Engineer on every destination. `preview` (count 1–20) = next runs of an expression.
- Server notes (tag Notes, `api/server_notes.go`, migration `create_server_notes`, `queries/server_notes.sql`): Markdown notes per server (≤200, body ≤100 KB), `pinned` ones on the overview; update takes `revision` (= `updated_at`) → 409. Viewer reads, Operator writes.
- Scripts (tag Scripts, `api/scripts.go`, migrations `create_scripts` + `script_runs_workspace`, `queries/scripts.sql`): saved scripts per workspace (`interpreter` bash|sh|python3, `run_as` user|root via `sudo -n`, `timeout_seconds` 1–86400, `params` passed as env vars, never spliced into the text) and runs (`POST /script-runs`: `script_id` or ad-hoc content → job `script-run`, `scriptParallel` 5 servers at a time, output capped at 1 MiB per server and saved ~every second; Stop = SIGTERM then the session closes after 5 s). A run keeps its own copy of the script and values. Running needs Engineer on every server; reading a run = `runLevel` (lowest level over its servers, at least the workspace level), Operator to read, Engineer to stop/delete.
- Terminal recordings (tag Terminal recordings, `api/recordings.go`, `internal/recording`, migration `create_terminal_recordings`): per-workspace setting (`/workspaces/{id}/terminal-recording`, off by default, `keep_days`, older ones purged). A recorded shell keeps its output (never input) as asciicast v2, gzipped in Postgres, ≤50 MiB (`recording.MaxSize`), saved every 30 s and on close; a shell cut by a restart shows `interrupted`. The cast of a live one comes straight from memory. Applies to shells opened after the change; the terminal WS `session` message + `TerminalSession` carry `recorded`. Lists filter to your own below workspace Owner (`everyone`); delete = workspace Owner, a live one → 409.

- Auth & access (`internal/auth`, migration `create_auth`, `queries/auth.sql`): argon2id passwords (≥12 chars), random opaque session token in an `HttpOnly` + `SameSite` cookie with only its hash in the DB, no JWT; uniform login error (blocked is only revealed after the right password), Redis login limits. `api/auth.go` = first-run setup (no users: creates the admin, needs `SETUP_TOKEN` when set), login, optional public registration (`pending` until approved; default off), own account. `api/admin.go` = members, groups, settings (system admin; the last admin can't be blocked/deleted, reject deletes the row, a temporary password forces a change at next login). `api/workspaces.go` = workspaces (every server/storage belongs to exactly one) + grants. Workspace look: columns `color` (app palette key, default indigo), `logo_kind` letter|icon|upload, `logo_icon`; image in `workspace_logos` (`api/workspace_logos.go`: `GET /workspaces/{id}/logo` = active, visibility checked inside, 404 otherwise, nosniff + CSP sandbox; `PUT` = admin, raw ≤1 MB sniffed by `appicon.Sniff`, sets kind upload); in the body empty = keep, `upload` needs a stored image (create refuses it), any other kind deletes the image; `logo_url` carries `?v=<updated_at>`. Levels: viewer < operator < engineer < owner, on a workspace or one server/storage, to a user or group; the highest wins; `can_create` (per grant on a workspace, default on for Owner only, admin-only) allows adding servers/storages. System admins have everything.
- **Every operation needs an entry in `policies` (`api/policy.go`): `public`, `session`, `active`, `admin`, `onServer/onStorage/onWorkspace(level)`.** `authz.go`'s middleware refuses anything missing and `policy_test.go` keeps them in step, so a new endpoint without a policy fails the tests. Raw chi routes are allowlisted in that test too and must call `authorize` themselves (terminal WS). `active` handlers filter lists with `principalOf(ctx).scope()`; endpoints taking several ids (bulk, transfer) check each with `requireServers` etc. Status: 401 no session; 403 with a detail for pending / must change password / too low a level; **404 when the user has no access at all**, so ids don't leak. Blocking, revoking or changing access is enforced at once on open terminals and streams (`authz.watch`/`sweep`/`track`). Origin guard on state-changing requests and the terminal WS. Levels worth remembering: cron run and everything that executes commands = Engineer; service details = Operator (they show environment values); credentials = Owner. Known gap: a server-files zip download already in flight isn't cut on revoke.

- Firewall: `api/firewall.go` (tag Firewall, `/servers/{id}/firewall…`): one collect script → overview (backend ufw/firewalld/nftables/iptables/none, rules, listening ports, zones, `capabilities`, `pending`), install (job `firewall-install`), enable/disable, rule add/update/delete, settings, reset, keep/undo, log, raw. `internal/firewall` only parses and builds commands (tests in `firewall_test.go`); it runs nothing. Writes go through `h.firewallChange` + a `fwPlan` (`cmds`, `risky`, `summary`). A `risky` plan (could lock Morcheh out) is the safe apply: snapshot + `rollback.sh` in `/run/morcheh-firewall`, an armed token, a detached 90 s timer on the server, then a fresh `sshprobe.Dial` (not the pooled conn, an established session survives a new block); no connection = rollback + 422. Keep/undo need the token (exit 3 = nothing pending). ufw comments are hex in `user.rules`: `Raw` drops them, `Comment` has the text. firewalld: `firewall-cmd`, or `firewall-offline-cmd` when the daemon is down (every call under `timeout`: a broken dbus hangs); rules listed for active zones + the default one. Also: port forwards `firewall_forwards.go` (ufw: `before.rules` + a companion route rule for remote targets, commented `Port forward (added by Morcheh)`; firewalld: forward-port + masquerade; `internal/firewall/forward.go`; a remote forward turns on IP forwarding and removing it never turns that off, since Docker/VPNs may need it), reorder = rule `move` (ufw only, `UFWMove` = delete + exact re-add), history `firewall_history.go` (table `firewall_changes`, last 50 per server, each with a snapshot; restore has a preview and is `risky` whenever the result is active), many servers `firewall_apply.go` (`POST /firewall/apply`, job `firewall-apply`, each server's outcome in the job log; a rule that could cut SSH off is refused).
- Fail2ban: `api/fail2ban.go` (tag Security, `/servers/{id}/security/fail2ban…`): overview (one collect script: installed/running/version, files, jails with status + timed bans), install/uninstall, service actions, `[DEFAULT]`/jail edits, raw jail.local, filters (`.conf` read-only, edits go to `.local`), ban/unban, log events, `test` (fail2ban-regex). `internal/fail2ban` only parses/edits text (line-preserving `Doc`, status/ban/log parsers, tests); it runs nothing. Writes go through `writeChecked`: backup, write, `fail2ban-client -t`, reload, restore on failure → 422 with fail2ban's message; stale `revision` → 409. Tasks answer `{ok, exit_code (-1 = timeout), output, truncated, duration_ms}`. `api/host.go` is the shared layer for modules that install a package and run a service (package manager + init detection, `packageScript`, `serviceScript`; servers without init run the daemon directly): reuse it for the next security modules (firewall, SSH hardening…).
- Users & groups: `api/users.go` (`/servers/{id}/users[/{user}[/password|lock|logout]]`, `/servers/{id}/groups[/{group}]`): one collect script reads passwd/shadow/group/login.defs/sudoers/lastlog/who; `internal/users` only parses. Every mutation runs as root (`rootShell`) and answers the fresh overview. `protect()` refuses lock/remove/rename/sudo changes on root and the login user. Sudo levels: `none` = leave every sudo-granting group, `password` = join `sudo_group` (else a rule), `nopasswd` = rule in `/etc/sudoers.d/morcheh-<name>` (dots → `_`); single-user rules elsewhere get commented `# (disabled by Morcheh) `, multi-user rules → 422; checked with `visudo`, restored on failure. Lock = `usermod -L -e 1970-01-02`. Passwords hashed server-side with `GehirnInc/crypt` (sha512_crypt); BusyBox (Alpine) gets fallbacks for missing shadow tools.
- Services: `api/services.go` (tag Services, `/servers/{id}/services…`): list (systemd `systemctl show` of every service unit, or OpenRC `rc-status`; `init:none` = empty list), details (`systemctl cat` files + revision), logs (`journalctl -u … -o json`, `lines`/`priority`/`since`/`after`), SSE `logs/stream` (events `entry` / `problem`; empty `after` = `-n 0`), `action` (start/stop/restart/reload/enable/disable/mask/unmask/reset-failed/kill+signal; start/restart append `sleep 1` so a crash shows as failed; protected units (`services.Protected`: sshd, dbus, journald, logind, udev, network…) need `force` for stop/disable/mask/kill → else 422), PUT `override` (drop-in `override.conf`; empty = remove) and `file` (custom units in `/etc/systemd/system` only), POST create, DELETE (stop + disable + remove custom unit), `daemon-reload`. Unit writes: backup → write → `systemd-analyze verify` → daemon-reload (+ optional restart); a rejected file is restored (empty drop-in dir removed) → 422 with systemd's message; stale `revision` → 409. OpenRC maps start/stop/restart/reload/enable/disable/reset-failed (`zap`); mask/kill/override/create are systemd only (422). `internal/services` only parses.
- Power: `api/power.go` (`GET|POST /servers/{id}/power`, `DELETE /servers/{id}/power/schedule`): one script reports boot time, init, container, sessions, reboot-required (Debian file, `needs-restarting -r`, running kernel missing from /lib/modules) and the pending schedule (`/run/systemd/shutdown/scheduled`). Runs as root (`rootShell`; user-only = 403). Now = detached `setsid nohup sh -c 'sleep 2; …'` then the pool connection is dropped after 3 s; delays use `shutdown -r|-P +N` and need systemd (else 422 on `delay_minutes`); cancel = `shutdown -c`. Never test it on a server you need: the test container really stops.

- Docker (production): `Dockerfile` = Go build + Ubuntu 24.04 runtime with every tool the backend drives (ssh, sshpass, ansible + collections, bubblewrap, PGDG `postgresql-client-18`, mariadb-client, mongodb-database-tools, redis-tools; the build fails if one is missing), non-root `morcheh`, `tini` → `docker-entrypoint.sh` (goose up unless `MIGRATE_ON_START=false`, then `server`; `server reset-admin` skips migrations). **A new external tool the backend runs = add it to the Dockerfile (and its check list).** `deploy/compose.yml` + `deploy/.env.example` = Postgres, Redis, backend, frontend (built from `../../frontend`, `API_URL` baked in). bwrap needs `security_opt` seccomp, apparmor and systempaths unconfined in Docker (verified), else `ANSIBLE_SANDBOX=auto` runs without it.

## Structure & conventions

- `cmd/server/main.go` — wiring + graceful shutdown. `internal/config` — env config (`caarlos0/env`, `.env` loaded by godotenv). `internal/database` — pgx pool. `internal/api` — router (`api.go`) and one file per resource with Huma operations.
- New endpoints: `huma.Register` with `OperationID`, `Summary`, `Tags`; register them from `NewRouter`. Request/response types are Go structs (`Body` field, `doc`/`example` tags) so the OpenAPI spec stays complete — the frontend relies on it.
- Errors: return `huma.ErrorXXX(...)` (RFC 9457 problem JSON), not raw `http.Error`. File ops wrap SFTP errors with `fsError(path, err)` and return through `toProblem` (404/403/409/422/502).
- Huma: an input struct without `Body` isn't read, so streaming uploads grab `ctx.BodyReader()` in a `Resolve` method; repeated query params need `query:"x,explode"`; raise `MaxBodyBytes` (default 1 MB) for big JSON bodies.
- Schema changes only through goose SQL files in `migrations/`.
- Data access: sqlc (chosen over GORM/Ent: no runtime reflection, reads goose migrations as schema, native pgx/v5). Write SQL in `queries/*.sql` with `-- name: X :one|:many|:exec`, run `make sqlc`, use `sqlc.New(pool)`; never edit generated code. uuid → `google/uuid.UUID`, nullable → pointers (see `sqlc.yaml`).
- Cache: `internal/cache` — `cache.Get/Set/Delete` (JSON) and generic `cache.Remember(ctx, c, key, ttl, load)`; `cache.ErrMiss` on miss; raw client at `c.Client`.
- Logging: `log/slog` for app logs; chi `middleware.Logger` for access logs.
- DNS (tag DNS): any number of Technitium DNS Servers per workspace (table `dns_servers`, token sealed like other secrets, blank = keep). `internal/technitium` = HTTP API client (`Check`, zones, records, options; `AuthError` / `APIError` (Technitium's own message, shown as 422) / `NotDNSError`; built-in zones like localhost left out); dials through the same allow-list as direct databases (`allow_internal` = admin only; `tls_skip_verify` per server). API: `api/dns.go` (`/dns-servers` CRUD, test-connection, check, favorite, `/dns-servers/{id}/zones…` create/delete/enabled/options/resync), `api/dns_records.go` (records list/add/update, `records/delete`), `api/dns_options.go`, `/dns-zones` = every zone on every server of the workspace grouped by name with its copies (a server that didn't answer → `problems`). Background re-check `api/dns_monitor.go` (`DNS_CHECK_INTERVAL`, default 30s, 0 = off). Levels: Viewer read, Operator check/favorite/resync, Engineer zones + records, Owner edit/remove.
- Reverse proxy (tag Proxies; migration `create_proxies`, tables `proxies` (one per server), `proxy_hosts` (a site = `HostConfig` JSON), `proxy_changes` (history: every save snapshots all the proxy's sites, restorable)): `internal/proxy` = kind-neutral model (`HostConfig`, `Normalize`, `Validate` → `Problem{Field,Message}`, `Overlaps`) + driver registry (`Register`/`Get`/`Kinds`; a `Driver` renders files, inspects the server, parses existing config); `internal/proxy/nginx` = first driver (`parse.go` reads hand-written sites/certs, fixtures in `testdata`). New kinds (Caddy, Traefik, HAProxy) = a new driver package, no API change; the UI follows `capabilities` + `kind_label`. Plain SSH as root (no agent): setup (job `proxy-setup`) installs nginx if missing and adds one `include /etc/nginx/morcheh/*.conf`; Morcheh writes only its own files there, runs `nginx -t` and puts the old files back if it fails (422 with nginx's message), per-proxy lock, `revision` = host `updated_at` → 409. Hand-written sites are read-only. Types proxy/redirect/static/notfound + `stream` (TCP/UDP port forward: files in `/etc/nginx/morcheh/streams/`, inside the `stream {}` of `morcheh/stream.conf`, loaded from main context by `/etc/nginx/modules-enabled/zz-morcheh-stream.conf`; setup installs the stream module; `ProxyInspection.streams` says if it's ready). Live traffic `GET /proxy-traffic` (`api/proxy_traffic.go`): access logs read incrementally over SSH only when asked, counted per minute, an hour kept in memory; streams log with `log_format morcheh_stream`, so they count connections. `api/proxies.go`; background re-check `startProxyMonitor` (`PROXY_CHECK_INTERVAL`, default 60s). Levels = the server's: Viewer read (header values/raw directives redacted), Operator check/test/reload/logs, Engineer setup/sites/restore, Owner remove. **Gotcha:** Huma path/input structs must be exported, and an optional nested object needs `required:"false"`. Test on vm1 only.
- Database backups (tag Database backups, `api/database_backups.go` + `database_backup_run.go` + `database_backup_retention.go` + `database_restores.go`, tables `database_backup_plans`, `database_backup_plan_storages`, `database_backups` (`kind` full|incremental, `parent_id`, `position` = where the chain goes on, trigger schedule|manual|restore), `database_backup_copies` (one per storage: pending|stored|failed), `database_restores`; guide in the frontend): a plan = selection all|selected|pattern (one file per database) → up to 10 Storages + folder (`{year}{month}{day}`), run on the database's server or inside its container; a direct database runs on the server the plan names (`runner_server_id`), or **on Morcheh's own machine when none is set (the default)**: `database_backup_local.go` (`dumpScript.server == uuid.Nil` → `runLocal`: same stdin contract, minimal env (`localEnv`: PATH/HOME/TMPDIR/TZ/USER, never DATABASE_URL/SECRETS_KEY), own process group killed on cancel, `uuid.Nil` as the job ref so local runs queue together; `localTools(d)` = LookPath of each engine's tools, sent as `BackupOptions.local`; MSSQL and server-mode databases never run locally); dumped once, uploaded to every storage (a failed upload fails that copy only); optional own login, cron + timezone (empty = by hand), method full|incremental (`full_every_days`), retention days|gfs|forever (`database_backup_retention.go`: per database, never the newest, never a parent of a kept backup). Incremental = `dbbackup.Incremental`: MySQL binlog (log_bin + RELOAD/REPLICATION CLIENT/SLAVE), MSSQL differential; none for Postgres/Mongo/Redis; a broken chain falls back to full. **A plan runs with the access of whoever saved it last**, re-checked at run time. `internal/dbbackup` only **writes the scripts** (fed to `sh -s` over SSH, passwords via env or a private temp file, never argv) and checks files; the API streams stdout into the Storage. Restore (`POST /database-backups/{id}/restore`, history `GET /databases/{id}/restores`, `limit`/`offset`/`total` like the backups list): Owner on the database + Operator on a storage holding the whole chain + Engineer on the runner (`runner_server_id` `"local"` = this machine, `""` = the plan's runner, local without a plan; a nil runner on the restore row = local); `mode` replace (needs `confirm` = name, optional safety backup = trigger `restore`, Engineer on that storage) | new; `dbbackup.Restorable`/`RestoreInto`: pg_all + redis_rdb by hand only, MySQL chains/mysql_sql only into their own name, MSSQL local only; every file checked against its SHA-256 first. Kinds `database-backup`, `database-backup-restore` (no retry-job) and `database-backup-verify` (reads the file back, compares checksum + format). Delete = Engineer on every stored copy (dependents included, they go too). dbmon's `restore_test` check = "Backup check" (fed by verify). Live engine tests (compose `test-*` containers): `go test -tags dbbackuplive ./internal/dbbackup -run TestLive -v -count=1` (backups; `TestLiveRestore*` = backup → restore round trips incl. MariaDB binlog and MSSQL differential chains). `test-mariadb` runs with the binary log on for incrementals; the `mysql:8.4` image has no `mysqlbinlog`, so MySQL incrementals there fail with "isn't installed".
- Database monitoring: `internal/dbmon` (one file per engine: postgres, mysql (also MariaDB), mssql, mongo, redis; read-only — only kill + explain touch the database) → `Snapshot`; `evaluate.go` = check catalogue `Checks` + `Evaluate` + `Settle` (a level counts after two looks in a row); `changes.go` = per-database baseline (`Diff`, `first_seen` per client address, `MarkNew` flags addresses first seen < 24 h ago on the live answer). API in `api/databases.go` (live endpoint redacts query text below Engineer) and the background loop in `api/database_monitor.go`.

## Gotchas

- goose is a `tool` in go.mod (`go tool goose`), which pulls many DB drivers into go.mod as indirect deps — they are not compiled into the server binary.
- `make migrate-up` errors with "no migration files found" until the first migration exists.
- Postgres 18 image: volume mounts at `/var/lib/postgresql` (not `/var/lib/postgresql/data`).
- `SETUP_TOKEN`: set it on anything but a laptop, or whoever reaches a fresh install first becomes its admin. `TRUST_PROXY=true` only behind a proxy that sets `X-Forwarded-For`, or login limits can be dodged. `COOKIE_INSECURE=true` sends the session cookie over plain HTTP outside development. The panel and API must be same-site for the cookie to work.
- `server reset-admin` (`cmd/server/reset_admin.go`) runs outside the server process, so it can't call `invalidate`/`KillOwner`: deleted sessions end open connections at the next sweep (≤1 min) and a detached shell lives until `TERMINAL_DETACHED_TIMEOUT`. It clears the account's login limits in Redis (`api.ForgetLoginLimits`; keep it in step with the keys in `auth-login`), not the per-address counter. The password is never a flag. Production use is documented in `README.md` (`docker exec -it <container> /proc/1/exe reset-admin`, verified; needs the server as PID 1).
- `SECRETS_KEY` (base64 32 bytes, `openssl rand -base64 32`) is required; changing it makes every stored credential unreadable.
- Local SSH target for testing: `morcheh-test-systemd` (:2223, `ant`/`colony`, real systemd; has a `broken-demo` unit that always fails and an nginx override — use it for services/power/users; no firewall, and firewalld can't run in it (no D-Bus)). Firewall and anything needing a real server: test on **vm1** (panel server `vm1`, 192.168.56.102, ufw; user rule); don't touch vm2. The old compose `test-ssh` is gone.
- **Dev services are containers in this `docker-compose.yml` (user rule):** any service needed for development or testing (S3, later databases, …) gets a compose service here and comes up with `make up`, not a plain `docker run`.
- Storage test targets (compose, all on 127.0.0.1; the panel's saved storages point at them): `minio` = S3 API :9100 (console :9101, `morcheh` / `morcheh-secret`), `test-ftp` :2121 (passive 21000-21010, `ant` / `colony`), `test-webdav` :8090 (`ant` / `colony`). The stopped plain-`docker run` containers `morcheh-test-minio`, `-ftp`, `-webdav` are their old copies and bind the same ports: don't start them. Never touch the unrelated `minio` container on :9000/9001.
- DNS test targets (compose, 127.0.0.1, `technitium/dns-server:15.6.2`): `test-dns-1` console :5381 (DNS :5354, `ns1.morcheh.test`) and `test-dns-2` console :5382 (DNS :5355, `ns2.morcheh.test`), console login `admin`/`colony`; the panel connects with an API token made in each console (kept out of git).
- Database test targets (compose, 127.0.0.1): `test-postgres` :5434 (`ant`/`colony`, db `shop`), `test-mysql` :3307 (`root`/`colony`), `test-mariadb` :3308, `test-mssql` :14330 (`sa`/`Colony-2026!`), `test-mongo` :27018 (`ant`/`colony`), `test-redis` :6381 (password `colony`).
- WebDAV: Apache mod_dav 301-redirects `dir` → `dir/`, and Go's client re-sends that as a GET (PROPFIND reads HTML, DELETE "succeeds" doing nothing): `slashRedirects` in `storage/webdav.go` repeats the original method instead.
- Huma doesn't flatten an embedded unexported struct into a request body schema (the fields vanish, and unknown-property checks then refuse them): spell the fields out in a named struct (see `playbookUpdate` in `api/ansible.go`). Same for path/query params: an embedded `xxxPath` type declared inside a register func is ignored, `in.ID` stays empty and `uuid.MustParse` panics (500, empty body). Embed an exported package-level `XxxPath` (e.g. `SchedulePath`).
- Huma also names an inline (anonymous) `Body` struct after the handler's input/output type: two handlers whose types share a name (e.g. `RunListBody`) collide and the spec breaks; name the body struct yourself (`scriptRunList`).
- Huma names schemas after the Go type, so two response types with the same name collide: give storage types their own names (`StorageEntry`, `StorageListing`…).
- Server refuses to start if `DATABASE_URL`/`REDIS_URL` is missing or Postgres/Redis is unreachable; `/health` checks both.
- Compose ports bind to `127.0.0.1` only (host ports: Postgres 5433, Redis 6380, MinIO 9100/9101, FTP 2121 + 21000-21010, WebDAV 8090; no `restart` policy); local creds are `morcheh`/`morcheh` (Redis password `morcheh`). `make sqlc` fails with "no queries" until `queries/` has a .sql file.
